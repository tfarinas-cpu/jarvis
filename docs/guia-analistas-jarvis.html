JARVIS — Guía de instalación y uso para analistas

LAFISE · SLGMS · Versión 1.5.0 · Puerto 8000

1. ¿Qué es JARVIS?

Indexa tickets cerrados de SLGMS: causa raíz, solución, SQL, casos similares y CSAT (cuando el solicitante calificó en JSM).

3. Búsqueda y filtros

Tokens AND: sistema + error + reporte. Ej.: SISNET ORA-00942, SLGMS-2076.

Atajos: / buscar · Esc limpiar.

Filtros facetados

  • Sistema
  • Área usuaria
  • Analista
  • Solicitante (Informador en Jira)

Escribí para autocompletar con conteo. Limpiar filtros restablece todo.

Orden y fecha

  • Más reciente — últimos cierres
  • Relevancia — mejor solución documentada
  • Rango de fechas y Solo solución útil

4. Tarjeta de resultado

  • Enlace SLGMS-XXXX ↗ a Jira
  • Causa y solución copiables + SQL/comandos
  • Casos similares
  • Badge Solución débil si el cierre no ayuda
  • Badge ★ N/5 si hay CSAT JSM
  • Área, analista y solicitante en metadatos

40 resultados por página.

5. Modo oscuro

Usá el botón Tema (sol/luna). No forces modo oscuro en Chrome — JARVIS tiene tema propio lafise-dark. La preferencia se guarda en el navegador.

7. Calidad y CSAT

Botón Calidad: % solución/causa/SQL, CSAT promedio global, % calificados.

Ranking documentación por analista (mín. 5 casos): score = 50% solución + 30% causa + 20% SQL.

7.1 Insights & Prevención

Botón Insights: clústeres de tickets recurrentes (mismo patrón) con propuesta de mejora preventiva por clúster.

ConceptoSignificado
FrecuenciaTickets del patrón en el periodo (30/90 días / histórico)
ImpactoTickets × áreas afectadas × diversidad de informadores
CSAT bajoBadge rojo si hay tickets del patrón calificados ≤ 3
Score55% frecuencia + 30% impacto + 15% riesgo CSAT

Filtrá por periodo, sistema y cuántos clústeres mostrar (Top 10/20/30/50); expandí un clúster para ver acciones preventivas y tickets de referencia. Copiar resumen para un ticket de mejora o Exportar MD para gestión. Admin: npm run insights:generate.

Los tickets de despliegue/Cambio a producción y los trámites administrativos repetitivos de soporte (altas, desbloqueos, resets, accesos) quedan fuera del cálculo de patrones; la lista de analistas se administra en config/insights-excluded-assignees.json, sus tickets siguen apareciendo en Buscar y Calidad con normalidad. Cuando referencian el ticket de incidente que resolvieron, aparecen como ticket relacionado dentro del clúster.

8. Sincronizar Jira

  • Web → Sincronizar Jira (incremental)
  • node scripts\sync-jira-api.js --full (histórico)
  • npm run sync:satisfaction:backfill (CSAT histórico, admin, una vez)

9. Problemas frecuentes

10. Flujo del analista

Incidente → Buscar JARVIS (filtros + texto) → Casos similares
→ Resolver → Cerrar Jira (Tips JIRA) → Sync → Equipo indexa + CSAT
